Day list

Draft updated 2026-11-01 · Design, not a working product

Staff read it at a glance between sessions, so it is dense. The next session is the only coloured row, with the word "Next" as well, because that is the question at the desk. Rows have no hover or focus, because nothing in them acts.

Every state

At each size

The list sits in .daypage__list, and that pane is the container, so the table reads the room it really has. .daypage sets the next session beside it from 37.5rem of window. On a phone the next session comes first, and .daylist-nav drops to the bottom, in reach of a thumb. Keyboard order stays with the markup, so the day buttons come first there too. A retry is .daypage__retrybar inside the list pane, so it never shifts the day buttons, and on a phone it joins the bar at the bottom. Rules for the whole page read the named container app, because the pane is a container too. The full screens are on Staff day list.
