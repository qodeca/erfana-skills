## How it was run

Three batches in parallel (F1–F8, F9–F16, F17–F20), each a general-purpose subagent on Opus told to read `agents/finding-verifier.md` and follow its body, with the target, a one-line purpose, and its finding ids. No batch was given the answer key; the key was written into this file after the run.

## Limits of this run

- The fixture and the agent have the same author, and most false findings are clear-cut. This shows the agent works as designed, not how it does on real reviewer output.
- The agent ran through a general-purpose subagent that read the agent file, not as the installed `erfana:finding-verifier`, so its `tools` limit and `effort` setting were not in force.
- One run, one target, a plan only. No code target, no finding that should end as not proven, no empty or unreadable input, and no embedded-instruction case.
- The three skills that call the agent were not run end to end.
